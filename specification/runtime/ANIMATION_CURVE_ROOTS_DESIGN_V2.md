# 动画三次曲线：独立交点模型

本规格定义 `animation.curve.roots-v2` 的连续采样规则，最低 Runtime API 1.9。

## 生产接入契约

roots-v2 使用 Runtime API 1.9 和 `animation.curve.roots-v2` 必需特性。
JSON/CANEB 使用 1.1 容器。包含连续通道三次曲线的数据必须声明此 profile；
播放器在缺少声明时拒绝加载。线性和阶梯规则保持各自的契约。
扫描所有动画的连续通道，包括未播放、零混合和末尾键的声明；不把离散换图的未使用 curve
字段算作三次求值。报告表示使用了新规则，不能断言每个被列出的键都会有可见差异。

原生 `caneRuntimeProfiles` 记录升级到 version 2，增加 `curves: "roots-v2"`，
使用新的必需特性 `cane.runtime-profiles.v2`。version 1 仍可读写且缺少曲线来源记录，
不能在加载旧记录时自动补为当前规则。两个版本标记互斥并须与记录版本匹配，
使不理解新曲线语义的旧客户端明确拒绝。沿用已有影响报告、独立副本和草稿来源机制。

生产连续采样使用可失败入口；Graph 经 renderer-neutral Runtime API 共用同一求值规则，
不能保留旧十段分支作另一个显示答案。失败按既有采样事务回滚；原裸浮点便利入口维持
签名，失败返回 NaN，生产消费方必须使用 checked 入口。正式一致性套件在独立复核前
暂停声明，保留旧输入、答案和容差作为历史证据，禁止直接刷新旧 Golden 让测试变绿。

本节先规定接入要求，实际完成范围以进度与验证记录为准。

## 需求与独立依据

关键帧间的线性、阶梯、普通三次曲线、值空间三次曲线与按属性曲线都继续支持。
这里处理一条已经选择的三次曲线，保留端点和 Y 越界；不实现轨道混合、关键帧排序或事件。
时间 X 的控制值继续允许所有有限 binary32 值，包括回折和超出 [0,1]；不能为简化求解而禁止它们。

公开数学依据：

- [W3C 三次缓动定义](https://www.w3.org/TR/css-easing-1/#cubic-bezier-easing-functions)
  提供固定端点、两个控制点及按输入 X 求输出 Y 的模型。CSS 限制 X 手柄范围，本方案没有采用该限制。
- [Bézier 导数](https://pages.mtu.edu/~shene/COURSES/cs3621/NOTES/spline/Bezier/bezier-der.html)
  给出相邻控制点差构成降一次导数曲线。
- [de Casteljau 求值](https://pages.mtu.edu/~shene/COURSES/cs3621/NOTES/spline/Bezier/de-casteljau.html)
  说明重复仿射插值求曲线点。本实现自行写固定三次求值，不复制网页伪代码。

## 数学与分支政策

令 `B(P,u)` 为四控制值的三次 Bernstein 多项式。X 控制值为 `[0,cx1,cx2,1]`。
对于 `0<p<1`，选择闭区间 `[0,1]` 上满足 `B(X,u)=p` 的**最小参数 u**，再计算 Y。
端点输入单独规定：`p<=0` 返回原始 from，`p>=1` 返回原始 to，即使曲线在中间也碰到端点。
这一定义不会依赖固定采样网格。端点连续性不能在回折切换处无条件保证；这属于显式语义政策。

普通曲线把百分比 Y 映射到值域；在 binary64 中先构成
`[from, from+(to-from)*cy1, from+(to-from)*cy2, to]`，防止有限最终结果被中间 binary32 溢出破坏。
值空间曲线使用 `[from, from+dy1, to+dy2, to]`，保留 from==to 时仍可能出现的运动。
不钳制结果。需要颜色/alpha 等钳制的消费方继续负责自己的范围。

对一组控制值 P，自行展开导数：令 `d0=P1-P0, d1=P2-P1, d2=P3-P2`，
则导数除以 3 为 `A*u²+B*u+C`，其中 `A=d0-2*d1+d2, B=2*(d1-d0), C=d0`。
用稳定二次公式列出驻点：系数先共同缩放，`q=-0.5*(B+copysign(sqrt(D),B))`，
根为 `q/A` 与 `C/q`；A==0 使用一次式，D==0 合并重根。不同有限根不以任意 epsilon 合并。
驻点与端点把曲线分成单调区间，按参数顺序寻找第一个包含目标 X 的区间并二分。
驻点恰好等于输入时保留切触根，不能只找变号根而跳过它。

## 数值和工作界限

所有输入先检查有限性；中间值使用 binary64，最终只转换一次 binary32。
最终不能表示成有限 binary32 时返回明确错误，不钳制成最大值、不伪造端点或删除关键帧。
内核无可变外部状态，失败不留下部分结果；后续适配层必须保持帧/时钟原子性。

为保留靠近 1 的微小参数余量，将参数域分成两个半区：左区直接用 u；
右区以 `v=1-u` 和反转控制点求解，并从大 v 向小 v 搜索。求 Y 时仍使用这个 v，
不先把它减成一个舍入到 1 的 u。该分区是数值坐标选择，不是折线逼近。
每半区最多两个内部驻点、三个区间，不递归分配树；每个跨越区间最多 384 次二分，
通常在中点不再可分时提前结束。binary32 最小正输入与最大控制值之比约为 2^-278，
384 为该端点尺度及 binary64 有效位留出余量；这不是对所有病态曲线的精度认证。
极窄驻点、近重根和大值抵消必须通过独立用例继续检查，不能只凭这个迭代上限宣称数值正确。

## 验证要求

覆盖解析曲线 u³、1-(1-u)³、静止导数、三个交点、切触重根、值域仿射变换、
from==to、端点、负零、Y 越界、极端有限控制值和失败原子性。
代数因式分解及已知参数点提供独立答案。当前一致性矩阵见 [协议](CONFORMANCE_V1.md)。
