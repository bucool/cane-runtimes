# 循环事件区间的独立推导与精度修正

本规格定义事件区间的精确计数和稳定排序，不增加单独的行为 profile。

事件键相对循环起点的时间为 o，周期 D>0，其所有出现时刻为 kD+o，k 为整数。
前向遍历拥有 (s,e]，反向遍历拥有 [e,s)。首遍初始化单独处理，不并入这个周期序列。
因此索引范围由两端不等式唯一决定；算法必须保留开闭边界，不能用 epsilon 合并事件。

## 已独立发现的反例

1. D=1、o 为最小正 binary32，s=1、e=1.25：应有 k=1 的一次事件。
   先计算浮点 `(s-o)/D` 会丢失 o，误排除这次事件。
   对 s=0.75、e=1，同样误差会把本属于下一段的事件提前发出。
2. D=1+2^-23、s=34351353856、e=s+2048：精确有理数计算给出
   k=34351349761…34351351808，共 2048 次完成事件；旧商的舍入给出 2047 次。
   第一次完成实际在 s+2^-23。这些数均可由 binary32 精确表示。
3. 即使修好数量，把 kD+o 合成为一个 binary64 时间也可能让 o=0 和极小正 o
   排序相同。循环末尾、完成、下轮零点与极小正键必须按实际时序排序。

## 数学方案

- 商只用于估计整数索引。对邻近索引直接判断 `kD+o-bound` 的精确符号，修正开闭端点。
- 乘法以 `p=kD` 与 FMA 残差保存；将 p、残差、o、-bound 累加到四项无重叠浮点展开。
  TwoSum 保存一次加法的舍入误差，最终最高非零项决定符号。没有第三方 runtime 调用。
- 可输出事件范围内的循环索引须能精确表示整数。原始 s/e 为不同 binary32 值；若
  |s/D| 达到 2^52，单步至少跨越约 2^28 周期，超过既有百万事件上限。该区间继续
  使用计数预检拒绝，不新增任意的小时间/小周期限制。
  这一保证限定于公开 Runtime API 的预算；底层调用若自行放大到数亿事件以上，
  不能援引此预算证明其枚举精度。本阶段没有扩大底层自定义预算的支持保证。
- 普通循环事件保留 `(cycle, offset)`，将 o=D 规范为下一周期的零点。先按周期，再按
  offset，再按已有 end/complete/start 阶段与声明次序排序，反向反转。
  初始化事件总在本次遍历的后续交点之前。
- 墙钟相对位置用同一误差展开计算 `kD+o-s` 后再做比例，不先把巨大绝对时间相减。

## 验证要求

先通过公开 API 复现近零键的提前/漏发和正反向排序，再用 Python Fraction 独立计算
索引端点，涵盖正负时间、开闭边界、相切边界、极小 offset、非二次幂周期与大整数索引。
保持旧队列、阈值、上限和回滚测试；原 243 个正式案例及其容差不得因这个修正重生成。
补充基于独立代数的交叉淡入测试，来源分类与功能验证分开记录。
